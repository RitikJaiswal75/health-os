# TDD evidence: P0.1 crash reporting

**Source plan**: `.cursor/plans/p0.1_crash_reporting_aab6ba0a.plan.md` (local plan file; not in git)

## User journeys

- As a maintainer, I want every configured provider to receive the same report so Sentry and Crashlytics stay in sync.
- As a maintainer, I want an on-device outbox when every provider is unreachable so reports are not silently dropped.
- As a maintainer, I want to switch providers from a Cloudflare Worker without shipping a new APK.
- As a user of a health app, I want crash payloads to contain no medication names, notes, photos, or filesystem paths.

## Coverage and known gaps

Command: `npx jest --forceExit --coverage --collectCoverageFrom='src/core/observability/**/*.ts' --testPathPattern=observability`

Result (2026-09-22): **87%+ statements / 90%+ lines** on the TypeScript module (full suite). UI wrappers (`ErrorBoundary.tsx`, `ObservabilityBootstrap.tsx`) are excluded from Jest coverage because this repo's Jest environment cannot load `react-native-paper`; they are exercised on a dev-client device.

- Native Sentry.init / Crashlytics SDK init is mocked; end-to-end delivery is verified on a device with a release build or by toggling Worker primary/fallback.
- NDK handler exclusivity is enforced by Gradle excludes + `enableNdk: false`, checked after prebuild by `npm run verify-android-manifest`.
